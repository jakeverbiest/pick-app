## How we ship (decided 2026-08-05)

Don't cut a new EAS build + TestFlight submit for every fix. Most fixes are
pure JS/TS and don't need one.

- **`[OTA]`** — JS/TS only (services, components, screens). Ship via
  `eas update` — live on-device in seconds, no Apple review, testable same day.
- **`[Native]`** — touches Swift (watch/widget targets), Podfile, native config,
  or anything that needs a new binary. **Batch these** — hold until 2-3 stack up,
  or until an OTA batch is confirmed good, then cut one build.
- Only cut a build when there's at least one `[Native]` item ready, or a batch
  of `[OTA]` fixes is stable enough to want a permanent checkpoint (e.g. before
  a wider TestFlight round).

## Test-harness issues (NOT app bugs) — found 2026-08-17

`npm test` chains suites with `&&`, so the first failure hides every suite after
it. That masked two separate problems on the pre-walk run. Neither affects a
shipped bundle; both are tooling.

1. **`test:calibration` pointed at a file that never existed.** The script ran
   `src/services/__tests__/weightCalibration.test.ts`, which appears nowhere in
   git history. **Fixed 2026-08-17** — script entry and chain reference removed
   from `apps/companion/package.json`.
2. **`test:hoods` cannot run under tsx, and hasn't since 14 Jul 2026.**
   `polygonStats.test.ts` -> `neighborhoods.ts` -> `@react-native-async-storage`
   -> `react-native/index.js`, which uses Flow's `import typeof`. esbuild (under
   tsx) can't parse Flow and throws `TransformError`. Introduced by commit
   `6094187`, when AsyncStorage was added to `neighborhoods.ts` — not by any
   later neighborhood work. **Metro strips Flow, so the OTA/native bundle is
   completely unaffected**, and `tsc --noEmit` still typechecks the same file.
   Open: needs a Flow-aware transform (or a mock for AsyncStorage) to run again.
   `polygonStats()` is currently covered only by the typechecker.

Also noticed: **`aggregationFlow.test.ts` exists on disk but is not wired into
any npm script** — it has never been part of `npm test`. Unknown whether it
still passes.

Use `ota-tonight.sh` rather than bare `npm test` before a publish — it runs the
suites individually so one broken harness can't hide a real regression.
