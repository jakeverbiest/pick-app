# Live Activity — "cleanup in progress" card

Lock-screen + Dynamic Island card showing time · pickups · distance · neighborhood while a walk is active (iOS 16.1+).

## Layout

Two halves, in two different places — that split is the whole design:

| Piece | Where | Compiled into |
| --- | --- | --- |
| JS API (`start` / `update` / `end`) | `index.ts` | — |
| ActivityKit driver | `ios/LiveActivityModule.swift` | the `LiveActivity` dev pod |
| Attributes (app copy) | `ios/CleanupActivityAttributes.swift` | the `LiveActivity` dev pod |
| Attributes (widget copy) | `../../targets/widget/Attributes.swift` | the widget extension |
| Widget UI + `@main` bundle | `../../targets/widget/*.swift` | the widget extension |
| Walk lifecycle calls | `app/(tabs)/map.tsx` | — |
| `NSSupportsLiveActivities` | `app.json` | — |

**No Xcode steps.** The widget extension is declared in `targets/widget/expo-target.config.js` and generated by `@bacons/apple-targets` during prebuild, so it survives the `ios/` regeneration EAS does on every build. A hand-added Xcode target does not — that's why the earlier attempt never shipped.

## The duplicated attributes file

`CleanupActivityAttributes` exists **twice on purpose**: once in the pod (so the module can start the activity) and once in the widget target (so the UI can render it). There's no supported way to share one file between a CocoaPods dev pod and an Apple target, and duplicating it is the standard pattern in Expo Live Activity setups.

This works because ActivityKit matches an activity on the struct's **name and Codable shape**, not on the Swift module it was compiled into — the same reason Apple's own template works with the app target and the widget extension producing two distinct types.

**If you change a field, change it in both files.** They must stay structurally identical or the card silently stops updating.

## Build & test

- `npx expo prebuild -p ios --clean` regenerates `ios/` with both targets. Safe now — nothing in `ios/` is hand-edited.
- `eas build --platform ios --profile production` → submit to TestFlight.
- On a **real device** (iOS 16.1+): tap **Start cleanup** → the card appears on the lock screen and in the Dynamic Island, updates every few seconds, and disappears on stop.
- Not appearing? Check Settings → PICK → **Live Activities**, and Settings → Face ID & Passcode → **Live Activities** on the lock screen.

## Gotchas worth remembering

- The podspec platform **must match the app's** (`15.1`, from `ios/Podfile`). It was previously `16.1`, which makes `pod install` fail with a platform-compatibility error — so the module never linked at all. Version gating is done with `@available(iOS 16.1, *)` in the Swift instead.
- Target `name` in `expo-target.config.js` must have **no spaces** (EAS looks up the sanitized name; a space makes it search for a target that doesn't exist). Use `displayName` for the human-facing label.
- Colors: the card uses PICK sage `#2D5016`; tweak in `targets/widget/PickCleanupWidget.swift`.
